Read ideas/upstream-bug-reports.md first — it is the authority for this session. Its
"Before filing: one box run" section has the preflight, the prerequisites and the exact
command sequence as a fenced block. Follow it, steps 0 through 9.

This is a vanilla Ubuntu 24.04 VM: no Docker, no Dokku, no checkout. Step 0 clones the repo
and checks out branch poll-churn-retention-and-last-build — the retention line and the
`shepherd2 last-build` verb only exist there. If `hostname -f` does not resolve, fix it
before running the installer; that is the preflight check most likely to fail here.

Goal: gather the evidence two upstream bug reports need. Four outputs:

1. The transcripts and JSON dumps the sequence names, in ideas/upstream-bug-reports/.
2. `dokku report demo` — the issue form's required field.
3. Step 8's answer, the one genuinely open question: after builds:prune, does
   `builds:output demo <pruned-id>` print journald's copy, print nothing, or print the
   CURRENT build's output? The note lists the three outcomes and what each means. Do not
   reconcile the conflicting accounts in prose — the transcript decides.
4. Two things of ours that no box has ever run: confirm shepherd2-install's
   `builds:set --global retention 300` line fires (step 1 greps the install log for it),
   and exercise `shepherd2 last-build` for real — after the deploy, after the three no-op
   ticks, and again after the 16 that fill the window. That verb was written against
   canned JSON in a session with no box, so its assumptions about Dokku's actual output
   are unverified: that `builds:list demo --format json` returns an array rather than an
   app-keyed hash, that `duration` is a string like "1m43s", that `log_path` is absolute.
   Report what it printed verbatim, and anything it got wrong.
